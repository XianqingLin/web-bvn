## 1. 设计原则

1. **确定性模拟核心（core）是唯一真理来源。** 同一输入序列 → 逐帧相同状态，可哈希校验；渲染/联机/回放/AI 都建立在"喂输入、读快照"一个接口上。
2. **数据驱动。** 角色差异全部压进 JSON，core 只有一套通用引擎；新增角色 = 新增数据。
3. **联机不侵入逻辑。** 帧同步只是"输入从网络来而不是键盘来"；单机/联机/回放/对拍共用同一份模拟代码。
4. **重构优于复刻。** 原版源码是参考规格书；行为对齐手感，结构自由重写。
5. **对拍是脚手架。** 阶段 1 用它对齐手感，之后退为回归工具。

## 2. 分层架构

```
app → render → core ← net      （依赖只许向下；data 被各层只读）
```

core 独立成包并用 lint 切断向上依赖——"逻辑/渲染解耦"靠自觉守不住（原版逻辑层与显示列表深度耦合是反面教材）。core 纯 TS 无 DOM、可在 Node 运行（对拍/单测/服务端校验依赖此点）。

data 双来源互为交叉验证：`tools/exporter` XFL 静态提取 + `tools/runtime-ingest` 运行时 dump 转译（由 `tools/bridge` 注入原版 AIR 应用导出）。
交叉验证豁免（2026-11-20）：orihime 与 yachiru 运行时 dump 抓不到 defineAction（注入桥局限，不可解决），二者仅由 XFL 提取产出——已知盲区，接受"XFL 解析器恰在此处有 bug 无法发现"的残余风险。

## 3. core

### 3.1 帧模型：固定 60Hz 单逻辑帧（设定）

原版按画质在 30/60fps 间切换、动画与判定独立 30Hz 采样。移植版固定 60Hz 逻辑帧（原版 60fps 档、`SPEED_PLUS=0.5` 手感基准），30fps 档视为历史降速不移植。**一切计时帧化**——原版大量"0.1 秒窗口"是隐性的帧率依赖，用帧常量表达更诚实。

**原版数值移植换算规则**：时间性量（重力步长、速度阈值）一律 ×`SPEED_PLUS=0.5`；空间容差（吸附带、±10px 平台容差）与帧数类（动画帧/延迟帧数）**不折算**；特例 hurtTime = ms→30Hz 帧换算 + 原版偏移。重力用原版 `_g` 斜坡模型（离地预置初值、空中递增、封顶、上升段清零），不是线性积分——这是"坠落总能落在平台、只有击飞才穿台"手感的原因。

### 3.2 tick 管线（顺序即契约）

```
sim.tick(inputs):
  1 输入处理（位图→缓冲→意图）  2 意图决策（状态机）  3 物理积分（含牵引边界）
  4 推挤（body AABB）  5 [动画帧] 动画推进/判定区/帧触发器  6 [动画帧] 命中结算（P1→P2→道具→辅助）
  7 流程事件（死亡/计时/比分/能量）  8 输出（快照+表现事件+哈希）
```

定序不是洁癖：原版 ENTER_FRAME 回调迭代顺序未定义，是真实的非确定性来源。标注 [动画帧] 的步只在 30Hz 动画帧执行。

### 3.3 输入：位图 + 缓冲（设定）

持续型行为（移动/防御）直读按住位图；触发型（攻击/跳/技能）过缓冲器，按下后 `INPUT_BUFFER_FRAMES`（默认 6 帧）内有效。缓冲窗设 0 = 原版经典手感——一个常量取代原版"经典/非经典"双模式。帧同步只传位图，缓冲是两端本地推导，协议与缓冲参数无关。

**元层键 `Btn.back` 不进缓冲器**：原版 back 无缓冲语义，且加位会漂全量哈希基线；just-down 边照常推导。

### 3.4 版边：牵引边界替代相机耦合（设定）

原版"角色不跑出镜头"迫使逻辑读相机；其设计意图是"两角色拉开不超过一屏"，直接写成 `playfield = clamp(两角色中点 ± HALF_WIDTH, 地图边界)`，相机降为纯渲染。已知偏离：极端拉距时版边与原版可能差数像素——按重构定位接受；对拍手感受损再复议（回退方案 = 相机进模拟）。

### 3.5 战斗机制：阅读地图 + 语义红线

原版 `FighterMcCtrler`（~2200 行逻辑动画混合体）是规格书不是抄写对象；移植版用显式状态表（`{id, 动画, 结束条件, 可取消表, onEnter/onTick/onExit}`），状态码沿用原版枚举。受击/防御/钢身结算路径是手感核心，对齐优先级最高。

**阅读地图**（机制细节以各文件头注释为准）：

| 系统 | 代码入口 |
|---|---|
| 状态机/动作槽/连段 | `core/src/fighter/machine.ts` + `behaviors.ts` |
| 命中与受击结算 | `core/src/sim/hit.ts` |
| 物理/版边/推挤 | `core/src/sim/physics.ts` |
| 道具/attacker 元件 | `core/src/sim/attackers.ts` |
| 辅助 | `core/src/fighter/assister.ts` |
| 团队回合流/终局/多局制 | `core/src/sim/flow.ts` |
| 条件触发器求值/属性白名单 | `core/src/fighter/def.ts` |
| 快照/哈希/序列化 | `core/src/serialize.ts` |

**机制语义备忘**（改动对应语义前先读；这些规则散在多个文件，单看一处容易丢）：

- 静态 def 不进 SimState；快照恢复经 `Sim.fromState` 回注（defs/assisterDefs 经 `getDefEntries()` 回传）；
- 时间轴顺流：非循环攻击标签播尽且段尾无重定向、下一标签帧号连续 → 滑入续播（必杀 1 帧桩靠此播放）；
- `endAct` 只清槽置 FREEZE，不动播放头；收尾由播尽或 idle 触发；
- damping 是持久阻尼（每 tick 线性逼近 0），非一次性乘法；move 系附带清阻尼；
- 地面位移需 `actLabel∈{站立,走} && labelLock<=0`（行走物理标签门）；idle 清 labelLock；
- 防御定格：抬手段 3 帧后停住；`防御` 不在 LOOP_LABELS；解除防御 = 首帧钉 2 tick 后回站立；
- 资源恢复：落地与回待机都要补动作槽并恢复 jumpTimes，否则永久锁死；
- loop 触发 = 无条件回卷（进入触发帧即回，触发帧永不采样显示）；gotoAndPlay/gotoAndStop 保留同标签守卫，loop 不保留；
- 辅助 gotoAndPlay 无同标签守卫（loop 靠 rewind 保活）；步内跳转落点不 +1 推进；
- customFunc 单槽；辅助 owner 死亡退场判定在 customFunc 之后；
- 播尽移除在 `totalFrames−1`（原版 off-by-one 原样保留）；元件第 1 帧触发器不执行；
- 命中结算序全部 id 升序（替代原版 children 插入序）；逐区命中**无跨帧去重**（原版每帧重扫，一帧一目标至多一命中，跨帧多段靠受击无敌窗限频）；
- 命中停顿 `freezeTicks` 进哈希、火花 payload 不进（双哈希登记的典型例子）。

### 3.6 角色数据与帧触发器

角色差异在原版藏在 XFL 时间轴脚本里（module-map §6.2）；移植版 = JSON 数据 + 帧触发原语（原语表在契约；扩原语需契约/core/校验器三处同改）。数据化不了的复杂机制收进 `core/fighter/behaviors/` 插件目录，不污染通用引擎。

### 3.7 确定性

战斗路径无随机、数值只有四则运算，IEEE754 双精度跨端一致——不需要定点数。剩余隐患（迭代顺序、相机耦合、帧率常量、sortOn 稳定性）由契约硬规则消除。

### 3.8 快照与双哈希（纪律）

每个 tick 输出 `SimSnapshot`（渲染唯一输入、对拍唯一基准、失步检测载体）；`SimState` 可整体序列化恢复（rollback 预留）。

- **全量哈希**：整个 SimState 规范序列化（键排序 + IEEE754 规范字符串）FNV-1a——任何表示变化都漂移，联机失步检测要的就是这个。
- **行为哈希**：剥除表现/输入派生字段（denylist：`fighters[].input`、bullets/attackers 的 `name`）+ 空容器省略序列化。`tools/replay` 门禁只冻行为哈希——表示层改动不再漂基线，行为变了必然漂（denylist 漏登记只会多漂不漏报）。
- **登记纪律**：新 SimState 字段默认进双哈希；纯表现字段入剥除表须同 commit 更新 serialize.ts 注释与本文。
- 漂移归因用 `tools/replay/verify-drift`（工作区 vs HEAD 逐 tick dump）。**两次 dump 必须子进程运行**——同进程 ESM 缓存会让 HEAD 沿用首次加载的 dist，恒"零差异"假阴性（批次 22 教训）。

## 4. 数据与素材管线

### 4.1 图集采集（atlas-capture）

原版角色/辅助是矢量符号，必须运行时栅格化。**关键语义**：姿势美术画在内层子剪辑自身时间轴里，引擎逐 tick 驱动——单纯 `gotoAndStop(f)` 截不到姿势，capture 必须逐标签**镜像引擎时序**（推进子剪辑→截图→nextFrame 循环），输出帧号 = 内层绝对帧（与 core `animFrame` 一致）。像素哈希去重（166k 引用→46k 唯一帧）；shelf 装包 2048²、排序固定可复现。**锚点契约**：每帧记相对角色 root 原点的 bounds 偏移（原版翻转绕原点），render 端 `translate → scaleX(direct) → draw(偏移)` 复现。

### 4.2 流帧拼图（stream-sheet / hud-sheet）与逐帧清理红线

部署跨境单请求 ~250ms，逐帧 webp 让加载分钟级 → 按统一画布（全帧 union bounds，烘焙工具逐帧断言）拼成少量 sheet webp + 清单写回 baked JSON，渲染端按 sheet 装载、逐帧建 cell quad 纹理（HUD 同构，16 sheet）。**红线：逐帧文件已随发版即时清理——重跑 stream-sheet / hud-sheet 前必须先重产散图，否则直接 404。**

### 4.3 公用资产后台预热（warm.ts）

hitspark/bisha/HUD 是每局固定税（~8MB/88 请求），在启动装载完成后的网络空闲点后台预热：只进 HTTP 缓存、**不解码不建纹理**（战斗装载流程零改动；真纹理预热需 KTX2 支撑，未立项）。**非阻塞**是刻意的——阻塞启动页对菜单毫无用处，且晚高峰 8MB@53KB/s ≈ 2.5 分钟。

### 4.4 title 三层夹心（ui-pack 3b）

主菜单嵌套动画路线（2026-11-24 定案）：**纯构造**——放置/变换 keys 全部来自 SWF 标签语义（切片 45 swf-nest），不做模板匹配（旧校准路线已证伪，见 git 历史）。三层 = 底板（手术剔 fx + 顶层）→ fx 叠加层（运行时按 keys 摆放；播放头板帧同步推进、定格期按墙时走，与原版"嵌套 clip 一经放置持续走带"一致）→ 顶板（静态内容 + 色变换烘死）。特例：vs 扫光是 clipDepth 遮罩，烘合成帧规避运行时遮罩；**5DPLAY 导流横幅栈整段剔除**（他站广告不进重构版，2026-11-24 决策）。菜单装载时序纪律：贴图请求最先（连接池空闲）、节点字/版本字在双板首帧就绪后才构建（否则黑屏期文字先于动画显示）。

### 4.5 时间轴贴帧音

`baked/timeline-sounds.json`（`tools/sound-pack`），寻址 `<kind>/<id>`——fighter 与 assistant 基名 16 处相同，裸 id 键会互相覆盖（整包丢失教训）。播放纯 app 层：快照 animFrame 差分触发、首次 sighting 作静音基线——core 零改动、双哈希零漂移。

### 4.6 设置面板与键位（app 层设定）

- 设置 = 菜单内全屏浮层（偏离：原版独立整页舞台 goStage；网页端返回零成本）；音量**即改即存**、0~100% 十档循环（默认 0.3，2026-11-25 用户定案）；键位走 APPLY 草稿语义（原版对位）。
- 键位按 `e.code` 物理键绑定（NumLock/输入法无关）；冲突策略 = 与占用方**交换**（保证全局每键唯一）；ESC 保留不可绑。键位只影响输入层（键→ButtonMask 位图），sim 零感知。
- 原版"画质"含 30fps 逻辑帧率档——**不得照搬**（确定性红线要求逻辑帧率恒定）；画质降级为纯渲染选项，未立项。

## 5. 渲染层

### 5.1 视野基准陷阱（读代码最易踩）

逻辑坐标 **1000×600**，但原版游戏内容区 = **800×600**（root scrollRect 裁剪）——移植版视野比原版宽 25%。一切依赖"内容区尺寸"的演出层（HUD 钉边、切人横幅、相机 zoom 基准）必须显式选择按**原版 800×600 常量**还是按**可见逻辑区**适配，不能混用。已定适配：HUD 逐元素钉边 + 血条/能量条横向拉伸补空隙；切人横幅内容横向拉伸铺满可见区；autoZoom 的 dist 基准用 800×600 常量（zoom 节奏对齐原版，可见区照常铺满）。

### 5.2 渲染原则

PixiJS v8；渲染帧率与逻辑解耦——位置在最近两快照间线性插值，动画帧/朝向取最新；HUD 读快照绘制；音效/特效消费表现事件队列（事件带 tick 号，渲染层自行去重）。装载 `load(spec, onProgress)` 分步计数、`prime()` 修换场景首帧黑边、渲染器所有权沿 `BattleLoadout` 交接。

HUD 算法、切人插图装配、intro/start_final 字样等逐项实现细节在 `packages/render/src/`（battle.ts / hud 等），文件头有原版对位与偏离登记，本文不复述。

## 6. 联机层

### 6.1 对局调度：rollback（2026-11-22 定案，GGPO 范式）

背景：房间服迁 CF 后国内玩家到边缘 RTT 150~300ms，lockstep 的 50ms 输入延迟预算盖不住，稳态 ≈ 20~35 tick/s 的"平滑慢放"（实测十几帧体感）。机制：本地输入零延迟立即生效并上行；远端未到→按最近位图预测推进（无硬上限，GGPO 同款——双端停步互等在 rollback 下是死锁）；真输入到达且不符→`Sim.fromState` 恢复历史重演至当前 tick；重演段表现事件剥除（预测期已放过的音效/特效不撤回——GGPO 同款取舍）；哈希仅在无未决预测的槽位比对。**协议与服务器零改动**（input/hash 透传复用）。实现 `packages/net/src/rollback.ts`，门禁 rollback.test.ts（近零延迟收敛/纠正段事件恒空/种子失步/对端静默超时冻结/真实 relay 端到端）。core 三个预留接口（tick 纯函数、SimState 可序列化、输入只经 InputFrame）当初即按此设计。

### 6.2 房间服与节点选择（2026-11-22 立项；2026-11-24 澄清）

- 房间服 = 游戏自有（Node / CF DO），只做输入中继与房间管理，不跑模拟；平台不做联机（2026-11-16 定案），只给好友邀请（信息传递）与身份凭证。
- 多节点清单（CF Worker `/manifest` 下发，改清单不发版）+ 客户端并行 ping/pong 测速择优（score = rttP50 + 抖动 + 负载惩罚）。**玩家无手动切换**（2026-11-22 二次决策）：节点只由自动择优与跨节点加入锁定决定；菜单左下角状态块纯展示。
- 节点即上下文：房间属于节点，**匹配跟随当前节点池**；`matchNode` 仅作紧急回滚兜底（2026-11-24 澄清，消除"固定服池不割裂"的旧表述矛盾）。
- `?server=` 强制通道保留（最高优先级、跳过测速）；手填/强制 URL **禁用随机匹配**——不可信服能伪造对端输入/改种子（configHash 互验挡错配不挡恶意）。2026-11-24 随入口重构收窄：强制通道 = `?server=` 会话级参数（flow.serverForced），手填记忆（localStorage）随服务器地址编辑行下线废弃；禁匹配在菜单随机匹配子项置灰落实。
- 跨节点加入：深链 `?room=&node=`，目标节点 ≠ 当前 → 确认后锁定切换（确认框 2026-11-24 随入口重构落地：同节点直接自动加入、不同节点确认框、节点不可用提示框且不静默回退）。

### 6.3 产品形态定案摘要（2026-11-16 ~ 11-23；原 netplay-design.md 于 2026-11-24 并入本节后删除）

- **纯房码制**（2026-11-21）：房间一律私人，浏览房间/公开列表下线；加入凭 6 位房码或平台邀请；解散房码进冷却池近期不复用。
- **配对即开局**（2026-11-17 切片 37）：匹配成功服务器直接开房广播 `matched`+`start`，免房间页/准备门；`seed` 随 matched 携带（兼 sim seed 与地图抽取种子）。
- **匹配无地图阶段**（2026-11-21）：地图 = `maps[seed%n]` 两端同解；好友房保留地图选择（房主定图，默认"？"随机项）。
- **匹配固定团队 3+1**（2026-11-24）：撤销 2026-11-22 的 1v1 可选开关；客户端入队恒发 `queue.team=true`，服务器按偏好分池机器与 `matched.team` 回执保留不动。
- **异常流**：对局前——客座掉线房主继续等待、房主掉线解散回菜单、凭码失败明确报错（room-not-found / room-full）；无重连（断线即散）。对局中掉线判负/重连 2026-11-24 定案不做。
- 邀请上下文：入房上报 `game:invite-context {room, node}`、回菜单清空（契约见工作区 `../docs/platform-seam.md` §4）。

### 6.4 联机入口重构与邀请票模型（2026-11-24 立项定案）

- **结构**：加入/匹配在菜单原地完成、房间用统一浮层（参照 SettingsOverlay），只有真正开局才切场景；NetScene / MatchScene / RoomScene 场景页撤销；深链与 dev 直通落主菜单不出暗底页。
- **拍板**（2026-11-24 晚目检改版）：「加入房间」不走浮层——子项**按钮原位翻转变身成输入位**（板面即输入显示，无 6 格视觉，>6 位静默忽略），输满回车确认、Esc 收回变回按钮；**错误一律模态弹窗**（位数不足/入房失败，不上按钮）。房间仍为半透明暗底浮层（背景动画不断）；手填 URL 下匹配子项置灰（§6.2 红线的 UI 落实）；选人页联机返回直接回菜单。
- **邀请票模型**：接受邀请 = 打开游戏落主菜单挂邀请卡，点击卡片才入房——忙态约束由构造达成（入房动作只存在于主菜单态，战斗/匹配/加载天然走不到）；跨窗口忙判定用游戏侧同源 BroadcastChannel/localStorage 锁（锁带心跳，超时视为失效）。拍板：兑换失败**一律销票**（含连接失败——让 A 重新邀请）；票只留最新；A 侧不做撤回，死票靠兑票报错兜底；票 TTL 过期、兑换即清；票锁定节点在 manifest 下线时提示"节点不可用"，不得静默回退当前节点误报房不存在。
- 二期路标（有推送通道与身份凭证后）：同标签页接受即入房（平台→游戏推送）；服务器存在感（好友"在对局中"展示）。
- 落地注（2026-11-24，片①-④）：加入（6 格房码）/匹配（秒表+✕/VS 横幅）/房间（房码+复制、席位卡、模式、开始·准备/离开）均已收进主菜单浮层（`scenes/net-overlay.ts`，半透明暗底、键盘接管）；NetScene / MatchScene / RoomScene 场景页撤销；选人页联机返回直接回菜单；会话内回菜单不重播开场；深链跨节点确认框落地。服务器强制通道收窄为 `?server=` 会话级（手填记忆废弃，见 §6.2）。邀请票模型与平台侧 PlayPage 修复待片⑤。

## 7. 验证体系（harness 先行）

门禁工具与 core 骨架同期交付，不事后补：

| 工具 | 作用 |
|---|---|
| 确定性单测 | 同一输入序列跑两遍，逐帧哈希相等 |
| `tools/replay` | 输入剧本回放 + 行为哈希门禁（§3.8） |
| `tools/replay/verify-drift` | 漂移归因：工作区 vs HEAD 逐 tick diff |
| 对拍 | 原版桥接快照 vs 本地模拟逐帧比对（阶段 1 手感对齐） |
| 数据校验器 | JSON schema + 引用完整性（角色并行转译的验收闸门） |

对拍容差：位移 ±0.5px、数值与状态码相等；按模块豁免须逐条记录原因——接受有意识的偏离，不接受无意识的漂移。
